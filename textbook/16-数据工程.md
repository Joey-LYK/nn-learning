# 第16章 数据工程

> 本章学习目标：
> 1. 能说明"数据质量"与"数据数量"的关系，并举出低质量数据的三种典型问题
> 2. 能写出归一化（min-max）和标准化（z-score）的公式，并用 Python 实现
> 3. 能解释为什么输入尺度不统一会拖慢甚至毁掉训练，并用实验对比归一化前后的收敛速度
> 4. 能列举至少三种数据增强手段，并说明批量训练与在线学习各自的适用场景

## 从一个例子开始

两位厨师做同一道菜，菜谱一样、灶台一样。

- 厨师 A 拿到的食材：新鲜的肉、当天的蔬菜，分量刚好。
- 厨师 B 拿到的食材：一半是变质肉，蔬菜上全是泥，分量还少一半。

结果不用想也知道。哪怕厨师 B 手艺更高，也很难赢。

训练神经网络时，我们花大量精力讨论网络结构、优化器、正则化——这些都是"厨艺"。但有一条朴素的工程共识：**数据决定效果的上限，模型只是逼近这个上限。** 同样的网络，喂好数据和喂烂数据，结果天差地别。

本章就来讲"食材处理"的功夫：数据要多少、怎么洗、怎么切配。

## 数据量：多少才算够？

先给一条经验法则（不是公式，只是起步参考）：

> 训练样本数 ≈ 模型参数量的 10 倍到 100 倍

比如一个有 500 个参数的小网络，5000~50000 条样本比较稳妥；上一章说过，参数远多于样本，模型就会直接背答案。

但数量只是表面，真正重要的是三点：

1. **覆盖度**：数据要覆盖模型将来会遇到的各种情况。只用晴天照片训练的识别器，雨天必然抓瞎。
2. **均衡度**：各类样本数量要大致相当。1000 条猫、10 条狗的数据集，模型学会"一律猜猫"就能拿 99% 准确率——一个毫无用处的"高分模型"。
3. **真实性**：数据分布要和实际使用场景一致。用实验室理想环境的数据训练，拿到嘈杂的真实环境里用，效果必然打折。

这三点可以浓缩成一句话：**训练数据就是模型眼中的整个世界。** 世界里没有的东西——没覆盖的情况、被淹没的类别、与实际不符的分布——模型永远学不会。

## 数据质量：比数量更要命

低质量数据的三种典型问题：

| 问题 | 例子 | 后果 |
|---|---|---|
| 错误标注 | 猫的图片标成"狗" | 模型被教错，且大模型会把错误背下来 |
| 噪声/异常值 | 传感器故障产生 99999 的读数 | 梯度被个别极端样本带偏 |
| 重复/泄漏 | 同一样本在训练集和测试集都出现 | 评估结果虚假乐观（还记得测试集纪律吗） |

工程实践中的真实比例：一个项目里花在**清洗数据**上的时间，常常超过写训练代码的时间。这不是浪费，是性价比最高的投资——修 100 条错误标注，可能比把网络加深一层提升更大。

## 归一化与标准化：把食材切成一样大小

### 为什么需要？

用一个例子看问题。假设你要预测房价，输入有两个特征：

- 面积：60~200（平方米）
- 楼层：1~30（层）

网络第一层算的是 $z = w_1 x_1 + w_2 x_2 + b$。面积是 150 时，$w_1$ 只要动 0.01，$z$ 就变化 1.5；楼层是 20 时，$w_2$ 得动 0.075 才有同样的效果。

后果：**两个权重需要的"合适学习率"完全不同**，可学习率是全局统一的。调大了，$w_1$ 那边震荡发散；调小了，$w_2$ 那边爬得极慢。损失地形被拉成一条狭长的山谷，梯度下降在里面左右横跳。

```
  不归一化的损失地形            归一化之后
  （狭长山谷，震荡前进）         （接近圆形，直取谷底）

   w2 ↑                        w2 ↑
    │  ╭──────────╮             │   ╭──╮
    │ ╱            ╲            │  ╱    ╲
    │ │   →→↘→→     │           │ │  →↓   │
    │ ╲            ╱            │  ╲    ╱
    │  ╰──────────╯             │   ╰──╯
    └──────────────→ w1         └──────────→ w1
```

解决办法：把所有特征缩放到相近的范围。常用两招。

### 招式一：归一化（min-max normalization）

把数据线性压缩到 $[0, 1]$：

$$x' = \frac{x - x_{min}}{x_{max} - x_{min}}$$

$x_{min}$、$x_{max}$ 是该特征在训练集里的最小值和最大值。

数值例子：面积特征，训练集中最小 60、最大 200。某样本面积 130：

$$x' = \frac{130 - 60}{200 - 60} = \frac{70}{140} = 0.5$$

恰好落在区间中点，合理。

### 招式二：标准化（z-score standardization）

把数据变成"均值 0、波动幅度 1"：

$$x' = \frac{x - \mu}{\sigma}$$

符号解释：$\mu$（mu）是均值，$\sigma$（sigma）是标准差（还记得第 5 章讲的吗——它衡量数据偏离平均的典型距离）。

数值例子：楼层数据均值 $\mu = 15$，标准差 $\sigma = 5$。某样本楼层 25：

$$x' = \frac{25 - 15}{5} = 2$$

含义是"比平均水平高 2 个标准差"。标准化后大部分数据落在 $[-3, 3]$。

用面积和楼层的例子，把归一化前后的数据分布画在同一把尺子上对比，直观感受"尺度统一"是什么意思：

```
 归一化前（横轴共用真实尺度 0~200）：

 面积    |··········■■■■■■■■■··········|                  60 ~ 200
 楼层    |·■■■|                                                1 ~ 30
         0                                                     200
         楼层被挤在角落里, 和面积放在一起几乎没有存在感

 归一化后（两个特征共用同一把 [0, 1] 的尺子）：

 面积    |······■■■■■■■■■■·······|   0 → 1
 楼层    |······■■■■■■■■■■······|   0 → 1
         两个特征占据相同宽度, 权重平起平坐
```

注意归一化只做了平移和缩放，**数据的相对分布形状不变**——原来挤成一团的还是挤在一起，原来稀疏的还是稀疏。它改变的只是单位，不是数据本身的结构。

### 两招怎么选？

- 数据有明显边界、分布均匀（如像素值 0~255）→ 归一化到 $[0,1]$，简单直观。
- 数据近似钟形分布、有少量离群值 → 标准化更稳，离群值不会把其他人挤成一团。
- 拿不准就用标准化，实践中它更常用。

### 一条铁律：用训练集的统计量

$x_{min}$、$x_{max}$、$\mu$、$\sigma$ 必须**只用训练集**计算，然后把同一组数应用到验证集、测试集和将来所有真实输入上。

为什么不能拿全部数据算？因为验证集/测试集扮演的是"未来的未知数据"，提前用它们的统计量等于偷看未来，又是一种数据泄漏。

工程上的落地方式：**把统计量和模型权重一起保存**。部署时每来一个输入，先套用保存的 $x_{min}, x_{max}$（或 $\mu, \sigma$）做变换，再送进网络。预处理参数是模型的一部分，不是训练完就扔的一次性计算。

## 数据增强：一份食材做三道菜

数据不够怎么办？一个思路：在保留"本质规律"的前提下，对已有样本做合理变换，变出新样本。这叫**数据增强（data augmentation）**。

关键前提是"变换不改变答案"。几个典型手段：

| 手段 | 例子 | 适用数据 |
|---|---|---|
| 加噪声 | 温度读数 ± 0.5° 随机抖动 | 传感器数据、数值特征 |
| 几何变换 | 图片旋转、翻转、裁剪、缩放 | 图像 |
| 缩放/偏移 | 音频音量乘 0.9~1.1，波形左右平移 | 音频、时序信号 |
| 混合样本 | 两个同类样本按比例加权平均 | 各类数值数据 |

混合样本举个例：两条"正常"工况的温度曲线，按 0.7:0.3 加权平均得到一条新曲线，标注仍是"正常"——介于两条正常曲线之间的状态当然也是正常。

反例：把"6"的图片旋转 180 度变成"9"——答案变了，这个增强就是造毒数据。**增强手段必须由人来判断"变换后标签是否依然成立"**，这是它无法全自动的原因。

数值例子体会一下"度"：温度传感器读数 23.5°C，标注"正常"。加 ±0.5° 抖动生成 23.2、23.8、23.6 三个新样本——读数变了，"正常"这个标签依然成立，增强有效。但若把抖动幅度设成 ±50°，造出 65.5°C 的样本仍标"正常"，就是在教模型"滚烫也算正常"——变换幅度大到改变了语义，增强就变成了投毒。

数据增强的本质：把"规律中不该变的东西"（如旋转不变性）显式地教给模型，让有限的数据发挥几倍的价值。

## 批量训练 vs 在线学习

数据怎么喂给模型，也有两种基本模式：

| 对比 | 批量训练（batch/offline） | 在线学习（online） |
|---|---|---|
| 数据 | 先收集齐全，存成数据集 | 边运行边收集 |
| 更新方式 | 每批算平均梯度再更新 | 来一个样本更新一次 |
| 优点 | 训练稳定、可复现、便于划分验证集 | 无需预先采集，能适应环境变化 |
| 缺点 | 要存储、要等待收集完成 | 早期预测差，易被异常样本带偏 |
| 适用 | 绝大多数项目 | 数据持续产生、环境会漂移的场景（如设备老化、用户口味变化） |

还有一个折中且最常用的方案——**小批量（mini-batch）**：每次取 16~256 个样本算平均梯度再更新。它比单样本稳定，比全量数据快，是现代训练的默认做法。

为什么"折中"反而两头占优？算两笔账：

- **全量的账**：一次更新要遍历全部 10 万条样本才算出一步梯度，方向很准，但走得极慢——同样的时间里只能走几步。
- **单样本的账**：每步只看一个样本，走得飞快，但单个样本的梯度方向噪声大，权重像喝醉了酒一样乱晃，损失曲线抖个不停。
- **小批量的账**：几十个样本平均后，噪声大部分互相抵消，梯度方向已经相当稳定；而每步计算量只有全量的几千分之一。同样的算力预算下，小批量能走成百上千倍多的步数，每一步的质量还过得去——总进度自然最快。

批量大小本身也是个要调的超参数：太小则梯度噪声大、训练不稳；太大则每一步又慢又贵，还容易陷进尖锐的局部最小值。16~256 是实践中反复验证过的甜区。

另外值得一提的组合策略：**仿真预训练 + 真实微调**。如果能用公式或模拟器生成大量近似数据（比如本章前面房价例子的规则生成），先用它把模型训练个八九不离十，再用少量真实数据继续训练修正偏差。真实数据的需求量会因此减少一个数量级。

## 动手实验

### 第一部分：归一化与标准化实现

这段代码实现归一化与标准化，并用一组房价特征演示：只用训练集计算统计量，再把同样的变换应用到验证集上。

```python
data = [
    (75, 5), (90, 12), (130, 20), (200, 30),   # 训练集：面积, 楼层
]
val = [(110, 15)]                                # 验证集

def stats(column):
    mean = sum(column) / len(column)
    var = sum((v - mean) ** 2 for v in column) / len(column)
    return min(column), max(column), mean, var ** 0.5

areas = [row[0] for row in data]                 # 只用训练集算统计量
floors = [row[1] for row in data]
a_min, a_max, a_mu, a_sigma = stats(areas)
f_min, f_max, f_mu, f_sigma = stats(floors)

def normalize(x, lo, hi):                        # min-max 到 [0,1]
    return (x - lo) / (hi - lo)

def standardize(x, mu, sigma):                   # z-score
    return (x - mu) / sigma

print("面积统计: min={} max={} 均值={:.1f} 标准差={:.2f}".format(a_min, a_max, a_mu, a_sigma))
print()
print("原始(面积,楼层)  ->  归一化面积   标准化楼层")
for area, floor in data + val:
    na = normalize(area, a_min, a_max)
    sf = standardize(floor, f_mu, f_sigma)
    tag = " (验证集)" if (area, floor) in val else ""
    print("({:>3d}, {:>2d}){:s} ->  {:.3f}        {:+.3f}".format(area, floor, tag, na, sf))
```

**预期输出**：面积的归一化结果都在 0 到 1 之间（训练集最小值映射为 0，最大值为 1）；楼层标准化后均值为 0 附近、大致落在 ±2 以内。最后一行验证集样本（110, 15）用的是训练集的统计量做变换——注意它的归一化结果约 0.286，并不落在训练集的端点上，这正是"把训练集学到的变换规则应用到新数据"的正确姿势。

### 第二部分：归一化前后的训练速度对比

第 13 章见过"量纲悬殊让梯度差几十万倍"，这个实验把它变成具体的时间账。用两个特征拟合 $y = 1000x_1 + 0.001x_2$（$x_1$ 是千米级小量纲，$x_2$ 是克级大量纲），让梯度下降跑到"平均损失小于 $10^{-6}$"为止，记录各用了多少步。

```python
def train(data, lr, target=1e-6, max_steps=300000):
    w1 = w2 = 0.0
    for step in range(1, max_steps + 1):
        g1 = g2 = loss = 0.0
        for x1, x2, y in data:
            d = w1 * x1 + w2 * x2 - y
            loss += d * d
            g1 += 2 * d * x1
            g2 += 2 * d * x2
        if loss / len(data) < target:
            return step, w1, w2          # 达标, 返回步数
        if loss > 1e10:
            return -1, w1, w2            # 发散
        w1 -= lr * g1
        w2 -= lr * g2
    return 0, w1, w2                     # 30 万步内没达标

raw  = [(0.001, 500.0, 1.5), (0.002, 100.0, 2.1)]   # 原始量纲
norm = [(0.5, 0.5, 1.5), (1.0, 0.1, 2.1)]           # 归一化后

for tag, lr in [("lr=0.00001", 1e-5), ("lr=0.000001", 1e-6)]:
    r, w1, w2 = train(raw, lr)
    if r == -1:
        print("原始量纲 {}: 发散".format(tag))
    elif r == 0:
        print("原始量纲 {}: 30万步未收敛, w1={:.3f}(真值1000) w2={:.6f}".format(tag, w1, w2))
    else:
        print("原始量纲 {}: {} 步收敛".format(tag, r))

r, w1, w2 = train(norm, 0.5)
print("归一化后 lr=0.5 : {} 步收敛, w1={:.4f}(真值2) w2={:.4f}(真值1)".format(r, w1, w2))
```

**预期输出**：三行对比非常扎眼——

- 原始量纲 + 稍大的学习率（$10^{-5}$）：直接发散，损失爆炸。
- 原始量纲 + 小学习率（$10^{-6}$）：不发散，但 30 万步后 $w_1$ 才爬到 0.002（真值 1000），等于几乎没学。
- 归一化后 + 学习率 0.5：**30 步**收敛到真值附近。

同样的数据规律，只是把特征缩放到同一尺度，训练速度的差距就以万倍计。归一化不是锦上添花，是训练能不能在合理时间内完成的分水岭。

## 常见误区

- 误区：数据越多越好，先爬一百万条再说。
  真相：一万条干净、均衡、覆盖全面的数据，胜过一百万条脏数据。先修质量，再谈数量。

- 误区：归一化时图省事，把全部数据（含测试集）一起算 min/max。
  真相：这是数据泄漏。统计量只能来自训练集，验证集和测试集必须"装作没见过"。

- 误区：数据增强就是随便变换，变换越多越好。
  真相：变换必须保证标签不变。旋转"6"得到"9"这类破坏标签的增强，是在给模型喂毒药。每种增强手段都要人工确认合理性。

- 误区：标准化（z-score）之后，数据就都落在 $[-1, 1]$ 里了。
  真相：标准化只保证均值 0、标准差 1，不设硬边界——大部分数据落在 $[-3, 3]$，但离群值变换后依然离群（这正是它比归一化稳的原因）。需要严格边界的场合应该选 min-max 归一化。

## 小结与下一章预告

- 数据决定效果上限。质量（标注正确、覆盖全、类别均衡）优先于数量，样本量经验值是参数量的 10~100 倍。
- 归一化（min-max 到 [0,1]）和标准化（z-score 到均值 0、标准差 1）统一各特征尺度，统计量只能用训练集计算，且要随模型一起保存。
- 实验结论：同一任务，归一化后 30 步收敛，不归一化 30 万步还不够——尺度统一是训练速度的分水岭。
- 数据增强用"标签不变的变换"扩充数据，但变换幅度不能大到改变语义，每种手段都要人工确认合理性。
- 批量训练稳定可复现，在线学习适应变化，小批量是实践中的默认选择；仿真预训练 + 真实微调能大幅减少真实数据需求。
